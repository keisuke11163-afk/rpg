- HUD-8／SFX-2 レビュー指摘の修正（`packages/core`・`arena-simulation.ts` は変えていない）：
  - **ボスの間で横に揺れない**：地図（512×448px）が画面の幅（640px）より狭く、`clampX` の最小と最大が同じになり横のずれが0だった。さらに Phaser は描画の前（`Camera.preRender`）に `useBounds` が true だと scrollX を `clampX` で切り詰めるので、bounds の外へ足したずれは画面に出ない。そこで `camera.useBounds = false`（切り詰めは `followCamera` が自分で行う。`clampX`・`clampY` は `setBounds` の値を使うので残す）にし、動ける幅が無い向きは `shakeOffsetWithinBounds` がずれをそのまま返す。`setViewOffset` には実際に足したずれを渡す（照準に漏れない）。`shakeWithinBounds` の仕様変更に合わせて「min=max なら base」のテストを「base + offset」に直し、min=max で base が範囲外・offset が NaN/Infinity・小数の base のテストを足した
  - **`SfxEventTracker`** が受け取った Map をそのまま覚えていた（同じ Map の中身が増えると前後が同じに見える）。トラッカーが自分の `Map<string, number>` を持ち、増えた技を見つけながらその場で書き換える。`ArenaScene` は `sim.uses` をそのまま渡す（毎フレームの `new Map` をやめた）。失敗中だったテストが通る
  - **被弾の揺れ**を前の版に近づけた（D-HUD-4）：被弾 2px・110ms、会心・崩し 1.5px・90ms。整数への丸めを確かめたところ、四捨五入では1.5pxの揺れの約3/4のフレームが0になったので、0 から離れる向きに丸める `roundShake` にした
  - **毎フレームの割り当て**：装備は部位ごとの uid の配列（使い回し）をトラッカーが自分の写しと比べる（文字列を作らない。`SfxObservation.equipment` は `readonly (string | undefined)[]` に）。`cameraBase`・`cameraShake`・`setViewOffset` の `{x,y}` は使い回す
  - **`sfx.ts`**：`onended` でフィルターも `disconnect`。コンプレッサーの knee を6dBと明示。周波数帯のコメントを実際の定義に合わせた
  - **連続ヒットの音**（D-SFX-7）・**通常攻撃の振る音**（D-SFX-8）：どちらも耳での確認はまだ（仮の判断）
  - **拾った音の検出漏れ**（D-SFX-9）：「持ち物が増え、画面を開いていない」に変えた
  - e2e：音量の行を、行の文言（「音量」）で探す（`settingsRowBoxes` に `label` を足した）。ボスの間で揺れを起こし、横にもずれが出る・カメラの左上が横に動く・照準が変わらないことを確かめる項目を足した（開発用の `aim()` に描画のカメラの左上 `viewX/Y` を足した）
  - **見え方の変化**：地域に入った直後のカメラが最初のフレームからプレイヤーに合う（`startFollow` の頃は、左上から約0.5秒かけて寄ってきた）。ボスの間（幅が画面より狭い）では、揺れで地図の外の空白が少し動いて見える

## 仕様の疑問
- 効果音：通常攻撃の近接は技の音を外した（D-SFX-8）。物足りなければ戻す。ヒットの間隔70ms（D-SFX-7）も耳で確かめていない
- 効果音：転職（G）で装備が替わると ui が鳴る。店で買う・装備を外すときは画面を開いているので pickup は鳴らない
- 敵の攻撃の予兆（溜め）・ボスの段階の切り替えの音は作っていない（今回の一覧に無い）
- 技以外から付く効果の名前（`hud.buff.*`）は仮の名前（特に `uniform-light` の「軽装の身のこなし」）
- 魔法使いの位相（最大3）も、個数で数えるゲージとして区切りを出すか（今は段階が1つあるので出していない）

    - 2回の長押し：星辰盤・職紋盤・副職紋のノードを返す
    - 1回のまま：設定の画面の行（音量・拡大率・詳しい情報・タッチ。取り消せる）、キャラクターの技の枠（次・前。取り消せる）、サブジョブの選択（候補を順に替える。取り消せる）、職紋盤↔副職紋の面の切り替え、鍛冶屋の装備の升（選ぶだけ）、画面の長押しのうち盤以外（副手に装備・技の枠を前へ・音量を下げる。D-TOUCH-7）。職紋盤の右の列の長押しは、振り直しの行では何もしない（その場で振り直してしまわないように）

  - **M1** 入力欄（input・textarea・select・contenteditable）に文字を打つキーは、PC の入力に数えない（`isTextEntry`）。e2e 追加

### 仕様の疑問
- 照準を離したとき：指示どおり最後の向きを覚える（D-TOUCH-6）が、補助仕様書1.2（ゲームパッドの案）は「右スティックを倒していないときは移動の方向を照準にする」。技のボタンをタップだけで使う人には、移動の向きに合わせる方が自然かもしれない（`aimFollowsMove` で切り替えられる）
- 技のボタンの「押した瞬間 pressed」と「ドラッグで狙う」の両立のため、0.12秒待つことにした（D-TOUCH-5）。待たずに出す・離したときに出す（MOBA のような「狙って離す」）のどちらがよいか
- 自動で狙う（近くの敵に照準を寄せる）補助は作っていない。片手で遊ぶ人には欲しいかもしれない
- **Q-TOUCH 画面（インベントリなど）・大きな地図を開いている間、タッチでは移動も回避もできない（PC は WASD で動ける。sim は止まらない。D-TOUCH-9）**。直していない（ユーザーの判断が要る）。候補：
  1. タッチの間は画面を開いたら sim を止める（ポーズ）。長所：開いている間に敵に殴られない・操作が分かりやすい・実装が小さい（`ArenaScene.update` で、タッチの表示かつ画面が開いているとき sim.frame を進めない）。短所：PC と違いが出る（PC は開いたまま動ける。ボス戦でインベントリを開いて薬を使う、のような遊び方がタッチでは変わる）。時間が止まるので、瓶・技の時間切れを利用できる
  2. 左のスティックと回避のボタンだけ残す（画面の外の余白・画面の下の隙間に出す）。長所：PC と同じく、開いたまま逃げられる。短所：画面が 624×300 とほぼ全体を覆う（D-TOUCH-9）ので置く場所が無い。画面の操作の指と取り合う（スティックの範囲が画面の左下と重なる）。誤って動かす・押す恐れ
  3. 今のまま（開いている間は動けない・敵は動く）。長所：何も変えない。短所：画面を開いている間に倒されることがある（タッチだけ逃げられない。PC との差が不公平）
  **決定（2026-11-16、ユーザー）：1（タッチの間は止める）**。D-TOUCH-15 として実装した：タッチの表示のとき、画面・大きな地図・「≡」のメニューのどれかを開いている間は `sim.frame` を進めない（`ArenaScene.isTouchPaused`）。メニューを開いている間は下端に「一時停止中」を出す。PC は今までどおり止めない。戻し方：`isTouchPaused` が常に false を返すようにする。e2e（タッチ 12b）で、開いている間は刻みが進まず、閉じると再開することを確かめている
- FIT のため、横長の端末（19.5:9）では左右に約75px、4:3 のタブレットでは上下に約96px の余白ができ、操作部はその分だけ内側に寄る。余白まで操作部を広げるには、画面の外（DOM）に操作部を置くか、拡大の方式を変える必要がある
- PWA（ホーム画面に追加。全画面・横向きの固定ができる）：今回は作っていない。iOS の Safari は Fullscreen API が無いので、iPhone で全画面にするにはホーム画面に追加（`manifest.json` の `display: fullscreen`・`orientation: landscape`）が要る。提案

### 実機で確かめてほしいこと（エミュレーションでは分からないこと）
1. 親指の届きやすさ：右の弧のボタン（特に技6・調べる・薬瓶）に、右スティックから親指を動かして届くか。左のスティックの範囲（左下の広い範囲）で、意図せずスティックが出ないか
2. ボタンの大きさ（直径44px）と間隔：押し違えないか。敵が親指・ボタンに隠れすぎないか（右下に敵がいるとき）
3. 照準のスティックの遊び（25%）と距離（1〜8m）：軽く触れて攻撃しないか・狙いやすいか。技のボタンの0.12秒の待ちとドラッグ（12px）で狙えるか
4. iOS の Safari：長押しでメニュー・文字の選択・拡大が出ないか（`-webkit-touch-callout`・`gesturestart`）、ダブルタップで拡大しないか、下のバー（ホームインジケーター）で操作部が隠れないか（safe-area）、アドレスバーの出入りで画面がずれないか
5. 音：最初のタップで効果音が鳴り始めるか（iOS は touchend で許す）。縦にして戻したときに音が戻るか
6. 全画面（Android の Chrome）：メニューの「全画面にする」で全画面になり、横向きに固定されるか。全画面をやめられるか
7. 縦持ち→横持ちで、止まって再開するか（その間に指が残って押しっぱなしにならないか）。着信・通知でタッチが取り消されたとき（touchcancel）に押しっぱなしにならないか
8. 画面の比率が違う端末（タブレット・折りたたみ）での操作部の位置
9. 長押し0.45秒・2回のタップで装備する、が煩わしくないか
10. （TOUCH-6）2回のタップが多すぎないか：鍛冶屋の右の列・商人の買う・祭壇・転移の石・振り直し・ロードアウトを2回にした。「選んだ」緑の帯と下端の「もう一度タップで決める」が分かるか。転移の石の移動も2回でよいか
11. （TOUCH-6）盤のノードを返すのに2回の長押し（0.45秒×2）が煩わしくないか。説明欄の「もう一度、同じノードを長押しで返す」が分かるか
12. （TOUCH-6）右スティックを離したあと、移動の向きへ照準が向く（後ろ向きに歩かない）か。技のボタンのタップが、移動の向きへ出て気持ちよいか（歩いている方向に出したくないときは、右スティックで狙ってから出す）。罠・煙玉・矢の雨・隕石のタップが、射程の半分（足元ではなく少し先）に出るのが自然か
13. （TOUCH-6）画面の左右の余白（844×390 で約75px）から触れ始めてもスティックが出るか。余白に親指を置いたまま動かせるか。iOS の Safari で、余白の touchstart が window に届くか
14. （TOUCH-6）アプリを切り替える・着信のあとに、押しっぱなしにならないか。裏に回ったときセーブされるか（ホームに戻って、アプリを閉じて、開き直す）
15. （TOUCH-6）設定が「出さない」のとき（PC のブラウザで触れる端末）、触れると「≡」が出て設定を開けるか。スマホでは「出さない」を選べないことの確認
16. （TOUCH-6）大きな地図（M）を開いたとき、左上の棒が消えて、「✕ 閉じる」だけが残るのが見やすいか
