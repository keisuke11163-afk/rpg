#### U-09 のレビュー指摘の修正（PR #12：Enemy.update の時間の検証・例外安全）

| 項目 | 内容 |
|---|---|
| 1. 時間の検証 | `Enemy.update` は `!(dt >= 0)` だけで、Infinity が通っていた。状態を変える前に、①経過時間が0以上の有限の数、②今の状態の経過時間に足しても有限、③その時間で最も速く動いても（移動・うろつき・帰還・突進の速さの最大）位置が有限、を確かめ、違えば RangeError |
| 2. 部分的な更新 | 修正前は「状態の経過時間 → クールダウン → 戦う者 → 行動の流れ」の順で、戦う者の更新（持続ダメージ・崩し・魔障の溢れ）で例外になると、経過時間とクールダウンだけが進んでいた。「検証 → 戦う者の更新（`Combatant.update` は自身で例外安全）→ 経過時間・クールダウンの反映（代入だけ）→ 行動の流れ」の順にした。経過時間・クールダウンは戦う者の更新に影響せず、行動の流れより前に反映するので、振る舞いは変わらない |
| 行動の流れの例外 | 行動の流れの中で例外を起こしうるのは、雲の状態異常の定義の確認だけだった（予兆 → 攻撃に変わった後に投げるため、状態が半端になる）。敵を作るときに計算・検証するようにした（データが正しくなければ、出現の時点で Error）。乱数の重み・範囲はデータの検証済みで、位置・向きの計算は検証済みの dt では例外を起こさない |
| 保証の範囲 | 上の検証または戦う者の更新で例外になった場合、敵の状態（行動の状態・経過時間・攻撃・位置・向き・クールダウン・HP・魔障・崩しゲージ・状態異常・うろつき・突進の距離）と乱数の状態は何も変わらない。行動の流れ自体は、検証済みの入力とデータでは例外を起こさないので、巻き戻しの仕組みは作っていない（想定外の不具合で例外が起きた場合の巻き戻しは保証しない） |
| 関係する箇所 | `Cooldowns.update`（敵が使う）に、残り時間を変える前の検証を追加。`EnemyField.update` に、敵を1体も動かす前の検証を追加（途中の敵で例外になり、前の敵だけ進むのを防ぐ） |
| 調べたが直していないもの | `JobGauge.update`・`TimedEffects.update` は `!(dt >= 0)` で Infinity が通る。`LingeringZone.update` は検証がない。いずれも U-07・U-08 の部品で、呼び出し元（`Combatant.update`・試験用の場の固定刻み）が先に検証しているため、今回は直していない |
| テスト | `enemy-update-validation.test.ts`（新）：Infinity・-Infinity・NaN・負の数・累計の溢れ・位置の溢れ（移動・突進）の拒否と状態の不変、戦う者の更新の失敗（溢れ・予兆・突進の途中・硬直・うろつき）の前後で状態が変わらず、その後も例外を経験していない個体と同じに振る舞うこと、dt = 0 と有限の dt で従来どおりなこと、`Cooldowns.update` の検証。`arena-simulation.test.ts` に `EnemyField.update` の検証を追加 |
